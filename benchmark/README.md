# V7 vs Fusion 固定评测

这套评测用于回答一个具体问题：在同一份真实字幕上，Skeleton First 融合版是否比 V7 更忠实、
覆盖更完整、父子关系更合理，也更适合复盘。评测不使用 LLM Judge；语义指标来自人工金标准和
隐藏身份的 A/B 盲测，程序只负责固定抽样、计分与汇总。

## 最省事的评估流程

在项目根目录执行：

```powershell
.\run-benchmark.ps1 serve
```

浏览器会打开三栏界面。左栏是样本和进度，中栏是带行号字幕，右栏是五步评测。每个样本：

不需要一开始做完 20 份。左栏默认“极简 3”：S002（技术概念）、S006（弱结构盘点）、S009
（长教程）。如果三份方向一致，可先形成 pilot 结论；方向不清楚再切到“核心 5”，补 S014 和
S018。只有需要正式、较强结论时才扩到全部 20。报告会用 `pilot / partial / complete` 标明完成度。

1. 只看字幕，写 8–12 个核心知识点、3–5 条结论；每行一条。
2. 点击字幕行后，可把 `L12-L18` 这类证据范围直接插入当前条目。
3. 锁定金标准；锁定前界面不会显示 A/B，避免反向迎合某个版本。
4. 对总结和固定抽样节点判断“支持 / 部分 / 不支持”，对金标准逐条判断“完整 / 部分 / 遗漏”。
5. 判断固定抽样的父子边，再完成四项 A/B 总体选择，点击“标记本样本评审完成”。

所有输入会自动保存。中途关掉页面也可以继续。顶部“生成报告”会把现有进度写进 `reports/`；
“导出标注”会下载金标准、评分和报告的 ZIP 备份。

金标准条目推荐写成：

```text
Skeleton First 先确定全局主干，再把内容挂到锁定分支 | L42-L61
每个节点应表达单一主张，细节放入子节点 | L73-L86
```

不要照抄整段字幕，也不要先看 A/B。核心知识点应是“如果漏掉就会影响理解”的内容；数字、专名、
条件和例外写入“重要事实与限制”。可选的一级主干只作为层级判断辅助，不把某一种树形视作唯一答案。

## 第二位评审者

请第二位评审者在页面顶部把名称改为例如 `reviewer2`，复核固定的 5 个样本：
`S002、S006、S009、S014、S018`。不同名称会写入独立目录，不会覆盖你的评分。报告会自动计算
逐项评分与 A/B 选择的 Cohen's kappa；低一致性意味着评分定义仍需澄清，不应直接宣称版本胜出。

## 命令

公开仓库不附带真实字幕或历史输出。先把 `seed-sources.example.json` 复制为
`seed-sources.json`，填入至少 20 条本地样本；每条记录包含样本 ID、来源 ID、标题、类别、字幕文件
路径，以及可选的历史 V7 输出路径。若要生成缺失的 V7 基线，还需设置
`V7_GENERATOR_PATH` 指向你有权使用的 `notes_structurer.py`。

```powershell
# 首次建立 20 份固定字幕、复制已有 V7 输出和空白标注模板
.\run-benchmark.ps1 setup

# 只生成缺少的 V7 输出；已有输出不会覆盖
.\run-benchmark.ps1 run baseline

# 生成 20 份融合版；已有完整输出不会覆盖
.\run-benchmark.ps1 run fusion

# 查看状态、校验冻结文件、离线汇总
.\run-benchmark.ps1 status
.\run-benchmark.ps1 verify
.\run-benchmark.ps1 score --reviewer owner
```

只调试个别样本：

```powershell
.\run-benchmark.ps1 run fusion --only "S001,S006"
```

`dataset.lock.json` 保存固定字幕和两版输出的 SHA-256。`verify` 只检查内容是否变化；如果主动重跑并
接受新输出，运行器会建立新的锁文件，因此应同时保留运行元数据和变更说明。

若部分基线来自历史冻结输出、部分在当前模型上补齐，最终报告必须把模型与生成时间差异列为实验限制；
成本和耗时的汇总也只能覆盖实际保留了运行元数据的样本。

## 指标口径

- Claim Support：输出中的总结和固定抽样节点是否能被字幕支持。
- Key-Point Recall：人工金标准的核心知识点是否被完整覆盖。
- Hierarchy Validity：固定抽样父子边是否真是组成、解释、方法、步骤、证据、例子或限制关系。
- Blind Pairwise：覆盖、层级、重复、学习价值四个整体判断。
- 自动指标：分支数、节点数、深度、空节点、精确重复、耗时和 token；只用于定位，不代替语义判断。

评分使用 `1 / 0.5 / 0`。报告必须同时展示样本完成数、失败案例和评审者一致性；未完成全部样本时，
结果只能视为阶段性数据。

## 目录

- `subtitles/`：冻结字幕。
- `outputs/baseline/`、`outputs/fusion/`：真实身份输出。
- `outputs/blind/`：给评审界面使用的 A/B 副本。
- `admin/blind-key.json`：A/B 映射；人工评测期间不要打开。
- `gold/`：人工金标准。
- `annotations/<评审者>/`：独立评分。
- `reports/`：CSV、JSON、失败案例与 Markdown 报告。

以上目录均是本地评测资料，不进入公开仓库。
